# Security policy

## Reporting a vulnerability

Use [Report a vulnerability](https://github.com/manovaspace/lighthouse/security/advisories/new)
to send a private report to the repository maintainers. Do not post exploit details,
credentials, student records or other sensitive information in public issues.

Include the affected version or commit, impact, expected and actual behavior, and
a minimal reproduction with synthetic data. Do not access real student accounts
or a private deployment to demonstrate an issue.

If the private form is unavailable, open a [routing-only issue](https://github.com/manovaspace/lighthouse/issues/new)
requesting a private channel, without vulnerability details. Wait for a private
channel before sharing those details.

## Supported versions

Security support covers the latest released Lighthouse version. Older versions
should be upgraded. Before the first release, maintainers may triage reports
against default-branch source; this does not establish production release support.

## Response and maintenance

The project owner monitors private reports initially. We target acknowledgement
within seven calendar days. Investigation, remediation and coordinated disclosure
depend on impact and the available fix; there is no fixed resolution deadline.

Maintainers must keep security-alert notifications enabled and check the private
report queue. The reporting form alone does not establish notification delivery.
See [GitHub's reporting and notification configuration](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).

General questions and bugs use [SUPPORT.md](./SUPPORT.md). Conduct reports follow
[CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md).
